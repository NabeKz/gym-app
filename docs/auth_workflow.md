# 認証の workflow

会員登録・ログイン・セッションのプロセスを、実装に落とす前の形で整理したもの。
記法は Scott Wlaschin『Domain Modeling Made Functional』にならう。

## 一覧

- 会員登録する
  - 訪問者がメールアドレスとパスワードで会員になる
- ログインする
  - 会員が資格情報を示してセッションを始める
- ログアウトする
  - 会員がセッションを終える
- 自分の会員情報を見る（view）

---

## 会員登録する

```
workflow「会員登録する」=
  triggered by:
    訪問者が登録フォームを送る
  primary input:
    メールアドレス AND 生パスワード
  output events:
    「会員が生まれた」
  side-effects:
    確認メールを送る ???
  失敗:
    既に登録されているメールアドレス
    OR 会員を保存できない

substep「メールアドレスの重複を確かめる」=
  input:  メールアドレス
  output: 未登録のメールアドレス OR 既に登録されている
  dependencies: メールアドレスで会員を引く

substep「認証情報を作る」=
  input:  未登録のメールアドレス AND 生パスワード
  output: 会員 AND 認証情報
  dependencies: ソルトを生成する

substep「会員を保存する」=
  input:  会員 AND 認証情報
  output: 会員が生まれた OR 会員を保存できない
  dependencies: 会員を保存する
```

---

## ログインする

```
workflow「ログインする」=
  triggered by:
    会員が資格情報を送る
  primary input:
    メールアドレス AND 生パスワード
  output events:
    「セッションが始まった」
  side-effects:
    セッショントークンを Cookie に載せる
  失敗:
    資格情報が一致しない
    OR セッションを保存できない

substep「資格情報を照合する」=
  input:  メールアドレス AND 生パスワード
  output: 本人と確認された会員 OR 資格情報が一致しない
  dependencies: メールアドレスで会員を引く

substep「セッションを始める」=
  input:  本人と確認された会員 AND 現在日時
  output: セッションが始まった OR セッションを保存できない
  dependencies: トークンを生成する, セッションを保存する
```

---

## ログアウトする

```
workflow「ログアウトする」=
  triggered by:
    会員がログアウトを選ぶ
  primary input:
    セッショントークン
  output events:
    「セッションが終わった」
  side-effects:
    Cookie のセッショントークンを消す
  失敗:
    なし

substep「セッションを終える」=
  input:  セッショントークン
  output: セッションが終わった
  dependencies: セッションを消す
```

---

## 自分の会員情報を見る

```
view「自分の会員情報」=
  input:  セッショントークン AND 現在日時
  output: 会員 OR セッションが無効
  dependencies: トークンでセッションを引く, 会員 ID で会員を引く

substep「セッションの期限を判定する」=
  input:  セッション AND 現在日時
  output: 有効なセッション OR セッションの期限が切れている
```

## data

```
data 会員 = 会員 ID AND メールアドレス
data 認証情報 = パスワードハッシュ AND ソルト
data 本人と確認された会員 = 会員

data セッション = セッション ID AND 会員 ID AND トークン AND 開始日時
data セッションの有効期間 = ???

data 既に登録されている = 登録済みのメールアドレス
data セッションが無効 =
     トークンが見つからない
  OR セッションの期限が切れている
```

`会員` と `認証情報` は別の data として置く。

`資格情報を照合する` の入出力に `認証情報` が現れないことが、境界の位置を決める。
パスワードハッシュとソルトは照合の内側にしか要らないので、
これを外に出す形にすると、認証情報の扱いが会員の外へ広がる。

---

## 補足

### 有効期間が未決

`セッションの有効期間` が `???` のまま。決まっていないので、
`セッションの期限が切れている` を判定する材料がない。

`app.sessions` は開始日時を持つので、値が決まれば判定はできる。

### 確認メールが未決

`会員登録する` の side-effects に置いた確認メールは `???`。
送らないという決定なのか、まだ手を付けていないのかが定まっていない。

### ログアウトに失敗を置かない

存在しないトークンでのログアウトは、結果として「セッションが無い」状態になり、
呼び出し側が取れる行動が成功時と変わらない。失敗として区別する意味がないため列挙しない。
